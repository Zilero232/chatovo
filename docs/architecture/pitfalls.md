# Pitfalls

Things that have already bitten us. Each one looked like a bug in our code, or a reason to swap a library, and was neither.

## Client

- **Rooms are addressed by a query param.** A room is `/room?id=…`, built by `buildRoomHref` / `buildRoomSearch` in `shared/lib`. It dates from the Next static export, which had no SPA fallback; invite links in the wild use it, so it stays, and the router keeps search params as plain `URLSearchParams` strings so those links still resolve ([web-app.md](web-app.md)).
- **The root `.env` makes a development build.** Its `NODE_ENV=development` is for the server, and Bun loads it into every script. `vite.config.ts` reads only the `NEXT_PUBLIC_*` keys and forces production for `vite build`; without that the web bundle ships development React.
- **A barrel re-export put LiveKit on the sign-in page.** `shared/lib` re-exports `screen-share`, which imports `livekit-client`; until `sideEffects` was declared, Rollup kept it in the entry chunk and `/auth` downloaded ~1 MB it never ran. Keep `sideEffects` in the web and ui-kit `package.json` and heavy screens behind `lazyRouteComponent` — [web-app.md](web-app.md#keeping-the-first-load-small).
- **A form without `noValidate` hides its own errors.** The browser checks `type='email'` / `type='url'` before `submit` fires, so `handleSubmit` never ran: sign-up with `tester` in the email showed no schema error at all, only Chrome's English bubble on one field (and nothing in a WebView that drops it). Every react-hook-form form carries `noValidate`; the Zod schema is the only validator.
- **The React Compiler froze the sign-up errors, and the tests didn't run it.** `SignUpCredentialFields` destructured `formState: { errors }` from `useFormContext()`. react-hook-form mutates `errors` in place, the compiler memoized the `FormProvider` subtree, and the child had no subscription of its own, so after a submit only the consent `Controller` showed its error. Vitest used plain `react()` without the compiler, so the test passed. Fields read `useFormState({ control })` now, and `vitest.config.ts` runs the same `reactCompilerPreset` as `vite.config.ts`, so a test sees what ships.
- **The auth splash covers only the first load.** better-auth refetches the session on window focus, and `useCurrentUser` reports `isLoading` again. `AuthProvider` shows the splash only until the session has resolved once (`hasResolvedRef`); gating on `isLoading` alone remounted the whole tree on every tab switch and wiped the forms on the auth pages.
- **Leaving a room can re-open it.** `close()` is synchronous and `router.replace` is not, so the room page re-requested a token and re-opened the session it had just closed. The session context remembers `leftRoomId`; see [room-session.md](room-session.md).
- **A LiveKit processor restart drops the `AudioContext`.** `TrackProcessor.restart()` is called without one on a device change. The voice gate caches the context from `init` and falls back to it; without that it crashed on every microphone switch. LiveKit has no built-in noise gate, which is why that processor is our own (`entities/app/settings/lib/voice-gate`).
- **A private room's password prompt must be reachable without a grant.** Reading a room once required a LiveKit grant, which only the password gives — so the prompt asking for it could never render. Viewing (`assertCanViewRoom`) and entering (`assertCanAccessRoom`) are separate checks on the server.
- **An `outline` doesn't follow the corners of a rounded `overflow: hidden` card.** The participant card's speaking ring was an inset outline and showed square corners; a coloured border alone got clipped at the radius. It is now the card border plus an inner `::after` ring with radius `calc(var(--radius-2xl) - 1px)` — [visual-design.md](visual-design.md#the-app-keeps-its-layout).
- **Base UI menus fail silently.** A `DropdownMenuLabel` outside a group stops the menu from opening, with no console error. The full list is in [guides/client/base-ui.md](../guides/client/base-ui.md).
- **A muted microphone sent audio.** LiveKit mutes by disabling the source `MediaStreamTrack`; the voice gate, detaching its processor on mute, restored the stream's `enabled` flag to what it was before it attached — `true` — so the room heard someone everyone saw as muted, and the server reported them speaking. A push-to-talk key pressed while muted did the same. `toggleMicStream` now refuses to enable a muted publication; every caller goes through it.
- **Push-to-talk came back open.** LiveKit sets the source track's `enabled` to `!isMuted` whenever it swaps the `MediaStreamTrack` — `restartTrack` (a device switch, new capture flags) and `stopProcessor` (leaving voice activity) — so an armed push-to-talk stream reopened on its own. `useMicActivationMode` re-arms on `TrackEvent.Restarted` and `TrackProcessorUpdate`, and the voice gate no longer restores the flag itself. Next to it: `setMicrophoneEnabled(true, options)` on an already published mic ignores the options, so new capture flags take `restartTrack` with the current `deviceId` (without one LiveKit falls back to the default device).
- **JS media queries and SCSS breakpoints must share a unit.** `bp(lg)` is `1024px`, and `MEDIA_QUERIES.wide` once was `64rem`: with a larger browser font the two disagreed, and the music dialog rendered the narrow tree into the wide grid. `MEDIA_QUERIES` is in px, matching `_breakpoints.scss`.
- **reactuse `useKeyboard(ref, …)` falls back to `window`.** While the ref is empty it listens on the window, and an element that never mounts keeps it there: the chat's edit dialog, closed for every message, swallowed every Enter in the room (the music link field, other dialogs). A key handler for one element is its own `onKeyDown`.
- **Profanity dictionaries are not interchangeable.** The chat filter (`widgets/chat/chat-panel/model/lib/censor-profanity`) takes each language from the source that handles it: English from `@2toad/profanity`, whose other languages are machine-translated (Portuguese `no`, `não`, French `les`, `pour`, German `Huhn` masked every message); German, Spanish, French, Russian, Ukrainian and Polish from `bad-words-next`, whose `*`-patterns cover inflected forms that a whole-word list like `russian-bad-words` missed (`пидоры`); Portuguese and Turkish from the LDNOOBW lists in `naughty-words`, matched whole-word by `@2toad/profanity`, because `bad-words-next` checks word edges with an ASCII `\b` and masked Turkish `ama`, `götürmek`. Every message runs through every language, so a word that is ordinary in one of our nine (`am`, `lust`, `mama`) goes on the whitelist. Russian infix patterns still hit a few ordinary words (`колебание`, `потребитель`, `страхуешь`); its `exclusions` take exact words only.
- **One listener's player error skipped the track for the whole room.** YouTube answers 150 for an age-restricted video, a region block or its own bot check — not only when the owner forbids embedding (oEmbed still answers 200) — and SoundCloud, Vimeo and file errors are just as often local. Each listener's player called `next`, so one person's restriction threw tracks away for everyone. Only error 100 (removed or private) skips now; everything else is told to that listener ([room-music.md](room-music.md)).

## Site

- **The standalone server must bind `HOSTNAME=0.0.0.0`.** Docker sets `HOSTNAME` to the container id, and Next's standalone `server.js` binds to it. next-intl's internal rewrite of a bare (Russian) path to `/ru/...` goes to `localhost`, misses the server and every page loops into a 307. The site Dockerfile sets `HOSTNAME=0.0.0.0`; keep it.
- **A scrollbar gutter on `body` as well as `html` shifted the page under the header.** `html, body { overflow: clip auto; scrollbar-gutter: stable }` made `body` a scroll container of its own that reserved a second, never-used gutter, so the fixed header was centred in a 15 px wider box than the content and sat 8 px off it. Only `html` scrolls and reserves the gutter; `body` keeps just `overflow-x: clip`.
- **A page that fetches the API must be `force-dynamic`.** Otherwise `next build` prerenders it, fetching the API at build time — in CI there is none, and the page ships with empty data until revalidation.
- **`next build` next to a running `next dev` can corrupt the dev manifests.** Both wrote `.next/dev/prerender-manifest.json` at once; every page then answered a bare 500, and `.next/dev/logs/next-development.log` showed `SyntaxError: Unexpected non-whitespace character after JSON`. Build with the dev server stopped, or trim the file back to valid JSON (or delete it and restart `bun dev`).
- **The site can't know who is signed in.** The session token lives in the app origin's localStorage; the header CTA is a static link into the app.
- **A relative `@use` inside `packages/ui-kit/styles` breaks the site build.** Under Turbopack the sass loader resolves the kit's partials through the package, so `@use 'breakpoints'` in `_base.scss` failed with "Can't find stylesheet to import" while Vite was fine. Kit partials reference each other as `@chatovo/ui-kit/styles/<name>`, like the rest of the kit.

## Server and production

- **`safeJsonParse` returns `{}` for a JSON array.** It is meant for objects (metadata, socket frames). An API that answers with an array — Radio Browser does — is parsed with `JSON.parse` in a `try` and validated with `z.array(...)`.
- **Missing Telegram notifications in production are the network.** The VPS is in Russia, where `api.telegram.org` is blocked. The bot goes through `TELEGRAM_PROXY_URL`; check that before debugging the notification code.
- **A voice channel is one Telegram message, edited in place.** `modules/telegram/voice-sessions.ts` posts it on the first join, edits it (debounced, `VOICE_FLUSH_DELAY_MS`) on every join and leave, and turns it into a summary — length and everyone who came — on `room_finished`. The session lives in memory: after a server restart the old message stays as it was and the next join starts a new one. Invisible admins never enter it — `participant_left` skips them just like `participant_joined`.
- **The dev database is on port 5433.** A Postgres installed on the host usually owns 5432; `P1000` against 5432 means the port is shadowed by it.
- **better-auth minor releases add columns.** A required column with no default fails the migration on a non-empty table — [ops/migrations.md](../ops/migrations.md).

## Desktop

- **The window icon is linked into the executable.** Swapping the icon files and restarting `bun tauri:dev` changes nothing; the binary has to be rebuilt (touch `build.rs` or clean the target).
- **An old icon in the taskbar jump list after an update is Windows' icon cache**, not the build. The binary and the AUMID are already right; clearing `iconcache_*.db` fixes the machine.
- **The start URL is `/lobby`.** `tauri.conf.json` opens it directly; `/` in the web app only redirects there.
- **The update check waited for sign-in.** `UpdateProvider` sat in `AuthedProviders`, so a signed-out desktop app never checked. It now wraps `AuthProvider` inside `AppProviders`; since each route layout mounts its own `AppProviders`, the silent startup check is remembered at module scope in `useCheckAppUpdate` and runs once per launch, not again after signing in.

## Android

- **Play rejects a bundle whose native lib is 4 KB aligned** ("must support 16 KB memory page sizes"). Up to 1.7.0 the aab was built with NDK r27c, whose linker aligned the `LOAD` segments of `libchatovo_lib.so` at `0x1000`; the zip side was already fine. NDK r28+ in CI and the rustflags in `apps/client/native/.cargo/config.toml` fix it — [ops/release.md](../ops/release.md#16-kb-page-size). The flags have to stay a `cfg(target_os = "android")` entry: the Tauri CLI sets `CARGO_TARGET_<TRIPLE>_RUSTFLAGS` itself, which would override a `[target.<triple>]` entry, while cargo joins a `cfg` entry with it.

## Tooling

- **`bun run test`, never bare `bun test`.** Bare `bun test` is Bun's own runner, not Vitest, and fails the suite.
- **`next dev` rewrites the site's `CLAUDE.md`** (`apps/landing`). The `<!-- BEGIN:nextjs-agent-rules -->` block is re-added on every run; committing it keeps the tree clean.
- **A performance symptom that survives two library swaps is not the library.** Repeat the action (a fast second time is first-mount or dev compilation), try a production build, or read a profile before swapping a third time.
- **A script that truncates a file and then writes it can leave Vite serving an empty module.** The dev server's watcher reads the file in between and caches the empty transform; the page then fails with "does not provide an export named …". Write through a temp file and rename, or `touch` the file to make Vite re-read it.
- **`tsc --noEmit` can report errors that are already fixed** when `tsconfig.tsbuildinfo` predates a change to an ambient `.d.ts` (the site's `messages.d.ts` locale union). Delete the `.tsbuildinfo` before believing it.
- **A host firewall silently stops the room presence in dev.** The LiveKit container posts its webhooks to the API on the host (`host.docker.internal:4000`, `infra/livekit/livekit.dev.yaml`); with `ufw` active the packets from the compose bridge are dropped, LiveKit logs `dial tcp 172.17.0.1:4000: i/o timeout` and then `dropped webhook`, and the channels panel keeps people who left and misses people who joined. Allow the docker ranges to reach the dev API: `sudo ufw allow from 172.16.0.0/12 to any port 4000 proto tcp`.
- **LiveKit's dev UDP range must sit below 49152.** Hyper-V/WinNAT reserves blocks inside the Windows dynamic range (49152–65535) and moves them on reboot, so `51200-51300` failed to bind with "forbidden by its access permissions". The range is now `40100-40200` in both `docker-compose.dev.yml` and `infra/livekit/livekit.dev.yaml`.
